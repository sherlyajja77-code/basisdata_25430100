## 2. Ringkasan Dasar Teori
DBMS bertindak sebagai pengelola penyimpanan, keamanan, dan pengaksesan data secara efisien melalui perintah SQL[cite: 181]. MariaDB menggunakan arsitektur klien-server di mana proses `mysqld` mendengarkan permintaan klien (seperti CLI atau phpMyAdmin) pada port TCP 3306[cite: 182].

Pengelolaan hak akses menggunakan prinsip *least privilege* dengan format `pengguna@host`, di mana akun `root` digunakan khusus untuk administrasi dan akun kerja terbatas hanya pada basis data milik proyek/praktikum[cite: 184]. Penggunaan repositori Git memfasilitasi pencatatan rekam jejak pengerjaan tugas dan proyek secara berkala melalui perintah commit dan push[cite: 184].

## 4. Jawaban Titik Analisis

### Titik Analisis 1: Pembekuan Harga Historis pada Nota
Harga barang pada katalog/tabel `produk` bersifat dinamis dan dapat berubah sewaktu-waktu akibat inflasi, penyesuaian pemasok, atau kebijakan toko. Jika nota hanya mengambil harga dari tabel produk secara langsung (*real-time*), maka saat harga produk di katalog naik, total nilai transaksi pada nota-nota lama di masa lalu ikut berubah secara otomatis. Hal ini merusak integritas riwayat keuangan dan menyebabkan laporan omzet historis menjadi tidak akurat. Menyimpan harga pada detail transaksi (*locking price*) menjamin data keuangan historis tetap konsisten.

### Titik Analisis 2: Penyimpanan Nilai Turunan (*Derived Value*)
* **Alasan tidak menyimpan:** Menghindari redundansi data dan risiko *anomali data* (ketidakselarasan). Jika jumlah unit (*qty*) atau harga satuan dikoreksi, nilai total harus ikut diperbarui manual; jika lupa, data menjadi salah. Nilai turunan dapat dihitung otomatis lewat kueri SQL (`SUM(jumlah * harga)`).
* **Alasan tetap menyimpan:** Optimasi kinerja kueri (*performance*). Pada sistem berskala besar dengan ribuan hingga jutaan transaksi, menghitung ulang total belanja dari baris-baris detail setiap kali membuat laporan keuangan membutuhkan daya komputasi tinggi. Menyimpan nilai total yang sudah matang di tabel `pesanan` mempercepat proses pelaporan.

### Titik Analisis 3: Deteksi Unsur Terlewat pada Matriks CRUD
Artinya terdapat entitas/tabel yang datanya dibutuhkan (*Read*/*Update*), namun tidak ada satu pun proses bisnis yang bertugas untuk memasukkan/mendaftarkan data awal ke entitas tersebut. Ini menandakan adanya **proses bisnis yang terlewat (*missing business process*)** dalam tahap analisis kebutuhan. Solusinya adalah menambah proses bisnis baru (misal: proses *Pengelolaan Data Master Pemasok/Katalog*).

### Titik Analisis 4: Pernyataan Kebutuhan Kabur vs Spesifik
Kata "aman" dan "cepat" bersifat subjektif, kualitatif, serta tidak dapat diuji secara objektif (*not testable*). Pernyataan kebutuhan yang baik harus spesifik dan terukur agar dapat divalidasi saat sistem diuji.
* **Perbaikan "cepat":** *"Waktu respons pencarian produk harus kurang dari 1 detik untuk beban hingga 10.000 data."*
* **Perbaikan "aman":** *"Kata sandi pengguna wajib dienkripsi menggunakan algoritma hashing dan hak akses data dibatasi sesuai peran (role)."*

### Perbedaan Kode Galat (*Error Code*) MySQL: 1044, 1045, dan 1142

Ketiga kode galat ini berkaitan dengan keamanan dan hak akses (*privileges*) pada basis data MySQL/MariaDB, namun terjadi pada tahap/level yang berbeda:

| Kode Galat | Pesan Standar MySQL | Penyebab Utama | Lokasi/Level Kegagalan |
| :--- | :--- | :--- | :--- |
| **1045** | `Access denied for user 'user'@'host' (using password: YES/NO)` | **Gagal Autentikasi Login.** Username salah, password salah, atau pengguna mencoba masuk dari *host* (IP) yang tidak diizinkan. | **Level Server / Koneksi Awal** (Belum berhasil masuk ke server MySQL). |
| **1044** | `Access denied for user 'user'@'host' to database 'nama_db'` | **Gagal Akses Basis Data.** Pengguna berhasil login ke server, tetapi **tidak memiliki hak izin** (*privilege*) untuk membuka, membuat, atau mengoperasikan basis data tertentu. | **Level Basis Data (*Database Level*)** (Sudah login, tapi dilarang masuk ke basis data tersebut). |
| **1142** | `COMMAND command denied to user 'user'@'host' for table 'nama_tabel'` | **Gagal Otorisasi Perintah/Tabel.** Pengguna berhasil masuk ke basis data, tetapi **tidak memiliki izin untuk menjalankan perintah tertentu** (seperti `SELECT`, `INSERT`, `UPDATE`, `DROP`) pada tabel/kolom spesifik. | **Level Tabel / Perintah (*Table/Object Level*)** (Sudah di dalam basis data, tapi dilarang eksekusi perintah khusus pada tabel tertentu). |

**Ringkasan Analogi:**
* **1045:** Anda salah memasukkan kunci/PIN di pintu luar rumah (gagal masuk rumah).
* **1044:** Anda sudah masuk rumah, tetapi kunci kamar tertentu tidak diberikan kepada Anda (gagal masuk kamar).
* **1142:** Anda sudah berada di dalam kamar, tetapi dilarang mengambil atau mengubah barang di meja tertentu (gagal eksekusi tindakan).

## 7. Pembahasan dan Kendala

* **Kendala:**  
  Muncul pesan galat `ERROR 1045 (28000)` pada tampilan phpMyAdmin setelah akun `root` berhasil diberi password melalui CLI[cite: 187, 191].

* **Pembahasan & Solusi:**  
  Masalah ini terjadi karena konfigurasi default phpMyAdmin bawaan XAMPP menggunakan metode autentikasi `auth_type = 'config'` tanpa menyertakan password[cite: 188, 191]. Solusi dilakukan dengan mengubah konfigurasi pada berkas `config.inc.php`, yaitu memperbarui nilai variabel `$cfg['Servers'][$i]['auth_type']` dari `'config'` menjadi `'cookie'`[cite: 188, 191]. Perubahan ini memaksa phpMyAdmin menampilkan form login manual untuk memasukkan username dan password yang valid sebelum memberikan akses[cite: 188].
